# [L3] UI: menu CONTINUE label and level select wiring

| Model | Wave | Area | Depends on |
|---|---|---|---|
| sonnet | 2 | ui | L1, L2 |

## Goal
START GAME / CONTINUE opens the level select; choosing a level starts it.

## Allowed files (the ONLY files you may change)
- qml/MenuScreen.qml
- qml/AppRoot.qml

## Interfaces (frozen)
- `qml/MenuScreen.qml` and `qml/AppRoot.qml`: existing properties, signals, `objectName`s stay. You ADD `MenuScreen.hasProgress` and the `"levels"` screen with child `levelSelectScreen`.
- Do not change any interface. If one looks wrong, report BLOCKED (AGENTS.md section 4).

## Acceptance test (read-only — never edit)
- File: `tests/qml/tst_level_flow.qml`
- ctest name: `tst_level_flow`
- Build + run (from the repo root; ALWAYS keep `--parallel 2`):
  ```bash
  cmake -S . -B build-agents/L3 -G Ninja >/dev/null   # once
  cmake --build build-agents/L3 --parallel 2
  ctest --test-dir build-agents/L3 --output-on-failure -R "^tst_level_flow$"
  ```

## Spec notes
- `MenuScreen`: add `property bool hasProgress: false`; the `itemStart` label is "CONTINUE" when `hasProgress`, else "START GAME". The `startGame()` signal stays as is
  (it now means "open the level select").
- `AppRoot`: `screen` may also be `"levels"`. Add `LevelSelectScreen { objectName: "levelSelectScreen"; id: levelSelectScreen; visible: root.screen === "levels"; focus: visible;
  unlockedLevel: root.engine ? root.engine.unlockedLevel : 1 }`. `MenuScreen.hasProgress` binds to `engine.hasProgress`. `MenuScreen.onStartGame` now sets `root.screen = "levels"` (it no longer
  calls `engine.startGame()`).
  `LevelSelectScreen.onLevelChosen: (level) => { engine.startLevel(level); root.screen = "menu" }`; `onBack: root.screen = "menu"`.
  `inGame` is unchanged, so the game screen appears once the engine leaves the Menu state.
